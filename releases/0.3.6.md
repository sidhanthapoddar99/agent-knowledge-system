# 0.3.6 — `superseded`, a third terminal status for work whose scope moved

The lifecycle had two ways to close an item and needed three. `done` claims the
work shipped. `dropped` claims the idea was abandoned. Neither describes the most
common real ending: **the work closed here because its scope moved somewhere
else** — absorbed into another design, folded into a later phase, reshaped into a
different item.

`superseded` is that third ending. It is terminal, it sits in the **Closed**
category with `done` and `dropped`, and it applies at **both the issue level**
(`settings.json` → `status`) **and the subtask level** (frontmatter `status:`).

**No content migration. `MIN_CONTENT_VERSION` stays at `0.2.0`.** This release
only *adds* a value to the fixed vocabulary. Every status you already use stays
valid and unchanged; nothing on disk needs editing. Set
`engine_version: "0.3.6"` in `site.yaml` when you upgrade.

Plugin: **`agent-ks` 0.8.6** — the CLI mirror, the validator rule and the skill
manual all move with the engine. Update both together.

**Engine `0.3.6` · floor `0.2.0` · plugin `0.8.6`** — tag `v0.3.6`.

## Upgrade

No migration scripts. The whole chain is:

```bash
git pull
./start doctor          # full build — confirms nothing broke
# then, in site.yaml:
#   engine_version: "0.3.6"
```

Set `engine_version` last, as always.

**If you ship a `replace`-mode theme, you owe one more variable.** The theme
contract gained `--status-superseded`. A theme that inherits (`extends:
"@theme/default"`) gets it for free and needs no change. A theme that replaces
the parent must declare it, or `scripts/checks/check-theme-contract.mjs` fails:

```css
:root               { --status-superseded: #7c3aed; }
[data-theme="dark"] { --status-superseded: #c678dd; }
```

## What `superseded` means, and when to reach for it

Pick between the three Closed statuses by asking what a reader should do next.

| Status | The claim it makes | What the reader does next |
|---|---|---|
| `done` | The work shipped | Reads the artefact — a diff, a screenshot, a test run |
| `dropped` | The idea was abandoned on purpose | Reads the comment saying why, and stops |
| `superseded` | The scope moved somewhere else | **Follows the arrow** to where the scope went |

That third row is the whole feature. Calling a scope move `done` overstates it.
Calling it `dropped` throws away the pointer, which is the one fact worth keeping.

### The `→` line is required, and the validator checks it

A `superseded` file must name where the scope went. Write a line opening with an
arrow, in the file's own body:

```
→ absorbed into phase-3 notes/10, decision D2
```

`agent-ks check issues` **warns** when the line is missing. Both `→` and `->`
count, and the line may be a list item or a blockquote — that is how people
actually write it. For an **issue**, the arrow line may sit in `issue.md` or in
any comment, because closing an issue by comment is common; both places are
searched before the warning fires.

### Agents may set it

`done` and `dropped` stay human-only on an issue or a subtask. `superseded` does
not, and an agent may set it at either level. It certifies nothing about the
work — it only records that the scope moved, which the agent that moved it is
best placed to write down. The `→` line is what makes that safe: a reader can
always go and check the destination.

### An agent log cannot be `superseded`

`RUN_STATUSES` still holds five values. A run's `status` answers *did the agent
finish*, and a run whose scope moved elsewhere did not finish — that is
`dropped`. This is the same reason `blocked` and `review` were already excluded
from runs: all three describe a work item, not a run.

## What changed in the UI

- **A new glyph** — a right arrow, next to the check (`done`) and the cross
  (`dropped`). It reads as "the scope left here".
- **A new colour token** — `--status-superseded`, violet, distinct from every
  other status in both light and dark mode.
- **Progress bars count it as closed.** The index-table bar now derives its
  "closed" count from the **category** rather than naming `done` and `dropped`,
  so a `superseded` subtask can no longer land in the `active` remainder. It also
  gets its own segment, and the tooltip names it when the count is non-zero.
- **The Guide panel and the tracker Guide modal list it automatically** — both
  read `STATUSES` from `issue-status.ts`, so the legend, the icon and the gloss
  arrived with the constant.

## Notes

- **Z, not Y.** The floor does not move. `MIN_CONTENT_VERSION` means "the oldest
  content that still works unmigrated", and all older content still does.
- **The direction that does break is backwards.** Content using `superseded`
  will not load on an engine below `0.3.6` — that engine's gate rejects the
  value as outside the fixed vocabulary. That is the version contract working as
  designed; declare `engine_version: "0.3.6"` and it is enforced for you.
- **Both status-vocabulary mirrors moved together** —
  `astro-doc-code/src/loaders/issue-status.ts` (framework) and
  `plugins/agent-ks/skills/agent-ks-docs/scripts/issues/_lib.mjs` (CLI). Every
  other surface reads one of those two, so nothing else had a list to update.
