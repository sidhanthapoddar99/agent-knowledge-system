# 0.2.3 — the link gate stops asking the wrong question

**A migration ships, and the floor does not move.** `MIN_CONTENT_VERSION` stays
at **0.2.0**. Your site keeps rendering exactly as it does today whether you run
the migration or not — this is the first release where those two facts are true
at once, and the reason is worth one line: a floor refuses content the engine
would **misread**, not content that is merely worse to live with.

Plugin: **`agent-ks` 0.7.3**. Update both together.

## Upgrade

**The symptom that brings you here:** `agent-ks check link-form` used to pass and
now reports errors, on files you have not touched.

```bash
python3 migration/0.2.3_slug-form-links.py detect  <your-data-dir>   # what and where
python3 migration/0.2.3_slug-form-links.py migrate <your-data-dir> --dry-run
python3 migration/0.2.3_slug-form-links.py migrate <your-data-dir>
python3 migration/0.2.3_slug-form-links.py verify  <your-data-dir>   # must exit 0
```

Then set `engine_version: "0.2.3"` in `site.yaml` — last, never first.

**Nothing a reader sees changes.** In this repo the same migration rewrote 300
links and the built site came out byte-identical: 86,452 hrefs across 1,216
pages, not one different. If you would rather not run it, your site is fine; you
keep the cost described below and the gate keeps reporting it.

**If the script refuses a link, it is telling you something.** A refusal means no
single file matches that target — a genuinely broken link rather than a slug.
Fix those by hand; the script will not guess.

## What's new

### `check link-form` now asks whether the target exists

The gate used to ask one question: *does this target start with a `/`?* That is a
check on the **shape** of a link, not on what it points at. So this passed:

```markdown
[Design philosophy](./design-philosophy)     ← the published URL
                                                the file is 02_design-philosophy.md
```

Relative, no leading slash, and nothing on disk with that name. It is the URL
wearing a relative costume — and unlike a site-absolute link, which at least
announces itself, this one looks exactly like the correct form.

**Nothing breaks in a browser**, which is why it goes unnoticed: the router
accepts both spellings. What you lose is everything the file tree gives you.

| | |
|---|---|
| `agent-ks move` | cannot follow it — rename the target and the link rots, silently |
| `grep <filename>` | does not find the reference; a file's inbound links are invisible |
| an editor, Obsidian, an agent | cannot open it |

The gate now resolves every relative target on disk, using the same arithmetic
`move` performs before rewriting a link. Two spellings that look fine and are
not: **dropping the extension** (`./20_themes/01_overview` where
`01_overview.md` exists) is skipped by `move` just like a slug is, so it fails
too. A **directory** target is fine — `move` maps directories as readily as
files.

### The gate stops skipping your issue tracker

It only ever looked at docs sections. The reason had been wrong twice, so it is
gone rather than given a third: measured across 1,843 links, including the
tracker cost **two** findings. A link in a tracker is exactly as unmaintainable
as a link in a docs page. `--all` is still accepted and ignored.

### `agent-ks move` stops editing your documentation

Two fixes, and the first is the one that matters — it **writes**.

- **Links inside inline code spans are left alone.** A link in backticks is a
  page telling a reader *what to type*. `move` tracked fenced blocks and nothing
  else, so it rewrote those examples into something else.
- **Titled links are maintained.** `[x](./y "why")` matched no pattern at all, so
  it was never reported, never counted, and never followed a file that moved. It
  now is — with the title preserved.

### A backticked path that names a real document is reported

`` `../25_themes/03_variables.md` `` quoted in prose is a reference nothing can
follow. This **warns**, and will stay a warning: a page whose subject is paths
quotes real ones as data, and no tool can tell that from a reference. Treat the
list as a prompt to look, not a work order. A non-document —
`` `src/loaders/paths.ts` `` — is correct and is never flagged.

## Notes

**Why this is a migration rather than a lint you can ignore.** The two link
rewrites this project has already lived through both fixed the *form* of a link
and left the *target* wrong, because every gate at the time tested form. A gate
that tests existence is what makes the class unrepeatable — and it can only be
turned on once the content is clean, which is what the script is for.

**On the warning that became an error.** The existence test shipped as a warning
and was tightened the same day, once this repo's tree hit zero. That was a
staging step rather than a judgement about severity: a gate that is red on
arrival is a gate people learn to ignore.
