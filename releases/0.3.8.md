# 0.3.8 — research is a default agent-log kind, and the Guide panel becomes a cheat sheet

Two engine changes, both small. `re` (research) joins the default agent-log
kinds, so a `NNN_re_<name>/` folder gets a symbol without an `agentLogKinds`
entry. The Guide panel on every issue is rewritten as a cheat sheet: short
lines, plain words, sections in workflow order, and it now describes the
agent-log shape the plugin scaffolds.

The larger change rides in the plugin. `agent-ks` goes from 0.8.6 to 0.9.1: the
skills are rebuilt, agent logs get their own skill, and Codex can install it.

**No content migration. `MIN_CONTENT_VERSION` stays at `0.2.0`.** Nothing on disk
needs changing — set `engine_version: "0.3.8"` in `site.yaml` when you upgrade.
Old agent logs render exactly as before; nothing checks their shape.

Plugin: **`agent-ks` 0.9.1** — see below.

**Engine `0.3.8` · floor `0.2.0` · plugin `0.9.1`** — released 2026-09-04, tag `v0.3.8`.

## Upgrade

No migration scripts. The whole chain is:

```bash
git pull
./start doctor          # full build — confirms nothing broke
# then, in site.yaml:
#   engine_version: "0.3.8"
```

Set `engine_version` last, as always. Then update the plugin:

```
/plugin marketplace update sids-plugin-marketplace
/plugin install agent-ks@sids-plugin-marketplace
/reload-plugins
```

## What's new

**Engine**

- `re` is a default agent-log kind, icon `book`. An issue that declared it in
  `agentLogKinds` keeps working; the override merges over the default.
- The Guide panel (`guide.ts`) is a cheat sheet. It drops the history asides and
  the old three-slot agent-log description. The status tables and the kinds
  table are still generated from code.

**Plugin `agent-ks` 0.9.1** (from 0.8.6)

- Nine skills. Every command is a skill folder, so Codex reads them too. New:
  `agent-ks-cli` (the CLI contract and the file templates), `agent-ks-logs`
  (agent logs), and the four commands as skills.
- Agent logs have one skill, `agent-ks-logs`. It states the two purposes of a
  log, when a run earns one and who decides, and the six kinds `lp`, `rf`, `au`,
  `re`, `it`, `wf` with a guided file set each. Every log starts with
  `00_index.md`. The shape is guidance: the scaffolder writes it, nothing checks it.
- Subtasks get standard sub-heads under the five sections: `Done when`, `Result`,
  `Agent log`, `Q&A`, `Issues hit`, `Watch out`. The subtask holds the outcome;
  the log holds the path.
- `agent-ks issue new-agent-log` picks a template by kind and takes `--for` to
  link the subtasks it serves; `--group <log>` opens a child log, numbered from
  120. `new-round` adds its line to the index.
- `agent-ks check issues --template` checks the `## Agent log` line of a subtask:
  `none` or one link that resolves.
- Codex: `.codex-plugin/plugin.json` ships in the plugin. Install through
  `sids-plugin-marketplace`, or with `npx skills add` for the skills alone.
- Removed: `agent-ks issue add-agent-log`. It wrote a loose file no other tool
  read. Write the file, then add its line to `00_index.md`.

## Notes
