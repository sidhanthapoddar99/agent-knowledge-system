The frontend asks for data by name and receives final, ready-to-display JSON; it recomputes nothing. The same shapes feed two consumers: the local client over the `/api` WebSocket, and the static renderer during `agentks build`. This leaf defines those shapes in `agentks-api` and implements the functions in `agentks-site` that produce them, so the server and the build cannot drift.

## Guardrails
- The shapes are a data contract, not rules: no function, formula or ordering logic crosses into TypeScript.
- Adding an optional field is not breaking; removing or renaming one is, and bumps `api_version`.

## Done when
- Every request above answers for the corpus through `agentks-site`, and the server and `agentks build` call the same functions (checked by a test that renders one page both ways and compares the JSON).
- `api.schema.json` is generated, committed and validated in CI; every fixture JSON validates against it.

# 04 Decisions
- Decided (sidhantha, 2026-09-29): the frontend holds display and UI logic only; every rule stays in Rust; no WASM.
- Decided (claude, 2026-09-30): the contract is published as a JSON Schema generated from the Rust types — a description of data shapes, not generated rules.

- Decided (claude, 2026-09-30): one number, `api_version`, versions both the message set and the data shapes, in the hello and in the manifest, as [050/20](../050_server/20_websocket-api.md) and [140/50](../140_versioning-and-migrations/50_protocol-version-handshake.md) describe. Sync framing is covered by the same number.
- Decided (claude, 2026-09-30): the client sends `hello` first (`api_version`, `client_build`); the server compares both and answers `ok: false, reload: true` on a mismatch (`dev` accepted in development). One place decides.
- Decided (claude, 2026-09-30): `get` is the cacheable pull (with `what` and `have`); `render` is its own `op`, as `open`, `save`, `doc.join` and the tracker operations will be, because an action has no hash to compare.
- Decided (claude, 2026-09-30): a diagram page's text is `source_text` and its language `lang`, because the page's `source` field is already the file path and a flattened body cannot reuse the name.
- Decided (claude, 2026-09-30): the sidebar sends no `order` field: the array order is the order, and a second copy would invite the browser to re-sort.
- Decided (claude, 2026-09-30): the issue detail carries the anatomy tree with URLs, not every sub-document body; the Comprehensive panel fetches bodies with `get page`, so an issue with 200 subtasks stays small.
- Decided (claude, 2026-09-30): the manifest's route table maps each URL to its section, its data key and the key's hash, so the client routes and cache-checks without computing anything.
- Decided (claude, 2026-09-30): `push: fatal` carries `errors` (every problem), not one `error`.
- Decided (claude, 2026-10-01): `open` and `save` reply through the usual `ReplyData`, whose `data` is `OpenResult` or `SaveResult` and carries the same `hash` as the reply, because every other result works that way and a second reply shape would add a case to every client. `OpenResult` and `SaveResult` are the last `ResultData` variants, because the enum is untagged and they have the fewest required fields; a test checks each fixture reads back as its own variant.
- Decided (claude, 2026-10-01): `open`'s `kind` is `markdown` or `diagram`, with `lang` present only for a diagram (an internally tagged enum), because the client needs the diagram language to pick its editor and the type then makes `lang` impossible to forget or to send with markdown.
- Decided (claude, 2026-10-01): a `conflict` failure carries the file on disk as an optional `current: { hash, text }` on `ReplyError`, because [050/35](../050_server/35_file-writes-and-echo-suppression.md) requires the conflict to carry the disk version and an optional field is not breaking. `OpenResult` and `current` share one `FileText` shape.
- Decided (claude, 2026-10-01): `SidebarNode.collapse_key` is the folder's path under its section written with URL slugs (`architecture/diagrams`), not the path on disk, because renumbering `NN_` prefixes is routine and must not reset a reader's folded folders. Two folders with one slug path already collide as URLs, so the key is unique wherever the site is valid.
- Decided (claude, 2026-10-01): the fixtures' Architecture folder lost its own page rather than its redirect, because the client's router test asserts that redirect and one URL has one owner either way; the Scripts folder now carries the "folder with its own page" case.
- Decided (claude, 2026-09-30): the fixtures are checked by a round trip through the Rust types rather than a JSON Schema validator crate, because the schema is generated from those types and a validator crate would slow every build; a one-off validator run confirmed the two agree.

# 05 Notes & Analysis
## 01 The TypeScript types come from the schema
The UI package generates its TypeScript types from `api.schema.json` with `json-schema-to-typescript` 16.0.0, into `src/data/generated/`. The [UI framework decision](../080_ui-and-client/10_ui-framework-decision.md) settled this; the detail is in [the shared UI package note, section 07](../../notes/03_frontend/01_shared-ui-package.md). Only data shapes cross over, never a rule, which keeps sidhantha's 2026-09-29 decision that no TypeScript is generated from Rust rules. [080/20](../080_ui-and-client/20_shared-ui-package.md) wires the generation.

## Watch out
- Keep `body_html` out of the manifest and indexes; they must stay small enough to send on every connect.
