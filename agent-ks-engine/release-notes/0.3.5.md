# 0.3.5 — tables stay readable under the Full Width theme

The bundled **Full Width** theme let a markdown table stretch to the whole
viewport. On a wide monitor a row then ran past 2000 px, and the eye lost the
row it was reading. The table now stops at the default theme's content width and
sits centred in whatever space the page gives it.

**No content migration. `MIN_CONTENT_VERSION` stays at `0.2.0`.** Nothing on disk
needs changing — set `engine_version: "0.3.5"` in `site.yaml` when you upgrade.

Plugin: **`agent-ks` 0.8.5** — unchanged this release.

**Engine `0.3.5` · floor `0.2.0` · plugin `0.8.5`** — released 2026-08-12, tag `v0.3.5`.

## The fix

The Full Width theme sets `--max-width-primary: none` so the page fills the
viewport. Nothing capped a table inside that page, so the table filled it too.

Three changes, all inside `default-docs/themes/full-width/`:

| File | Change |
|---|---|
| `element.css` | Declares `--max-width-table: 1336px` — the default theme's content width |
| `table.css` | New file. Caps the table at that width and centres it with `margin-inline: auto` |
| `theme.yaml` | Registers `table.css` in `files:` |

The rule targets `.table-wrapper`, which the `table-wrap` postprocessor puts
around every rendered markdown table, and the bare `table` element for
hand-written HTML. Both content containers are covered — `.docs-body` and
`.markdown-content`.

The width is its own token rather than a reference to `--max-width-secondary`.
The two are equal today. They are not the same idea, and a theme that widens its
content column should not silently widen its tables with it.

**The symptom this fixes:** under the Full Width theme, a table spans the entire
browser window with very long rows, while the surrounding paragraphs do not.

## Notes

- **Z, not Y.** No content format moved. CSS only, in one bundled theme.
- **Only the Full Width theme changes.** The default theme already capped its
  content column, so its tables were never affected.
- **You can override the width.** Set `--max-width-table` in your own theme to
  any value, or to `none` to restore the old full-bleed behaviour.
