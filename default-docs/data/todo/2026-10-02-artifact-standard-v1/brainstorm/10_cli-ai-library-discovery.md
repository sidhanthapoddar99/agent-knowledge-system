## CLI and AI-friendly component discovery

The owner wants agentks CLI—or whatever tool/API an AI agent uses—to make library navigation straightforward. An agent should quickly know what libraries and components exist and how to use them.

Discovery should help answer:

- Which libraries, collections, styles and categories are available?
- Which component fits a chart/table/object need?
- What inputs, events, state and assets does it require?
- Where are its source, documentation and working examples?
- What dependencies or compatibility constraints apply?
- What can be composed or reused instead of written again?

Descriptions, category metadata and typed component contracts need to be searchable. Machine-readable, bounded output is useful so agents can inspect relevant components without reading the entire repository.

Existing CLI/library lookup capabilities should be reviewed and extended for executable components and richer metadata. Listing a file is not the same as giving an agent a usable input/event/example contract.
