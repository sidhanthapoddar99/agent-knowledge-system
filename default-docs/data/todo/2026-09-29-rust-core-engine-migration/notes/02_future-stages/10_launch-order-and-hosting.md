agentks moves to the **neuralabshq** GitHub organisation, and its website is **agentks.neuralabs.org**: the homepage at `/`, the docs at `/docs`. The engine, client, homepage, docs and plugins live in one new main repository, and the default library in its own ([the repositories](./12_repositories-and-three-states.md)). The work runs in six steps. The Rust engine and the libraries come first; the website and the docs come last. Until the new docs are complete, this repository's docs and skills stay in use, and then everything switches at once. This repository is archived at the end.

# 04 Decisions

- Decided (sidhantha, 2026-09-30): the project moves to the neuralabshq GitHub organisation. Its domain is agentks.neuralabs.org.
- Decided (sidhantha, 2026-09-30): the website has two parts. `/` is the agentks homepage, a Next.js static build served by nginx. `/docs` is the docs, built with the Rust engine. A Dockerfile builds both (`agentks build` for the docs) and serves them with nginx. It is published later, not now.
- Decided (sidhantha, 2026-09-30): only the latest docs are published. No older versions.
- Decided (sidhantha, 2026-09-30): the install command's URL can be on agentks.neuralabs.org or a GitHub release; both work. The agentks.neuralabs.org one only passes the request on to the GitHub release.
- Decided (sidhantha, 2026-09-30): the Claude Code plugin marketplace moves from the personal account to `neuralabshq/plugin-marketplace`, serving all of Neuralabs. The personal marketplace stays for personal plugins.
- Decided (sidhantha, 2026-09-30): **plugin** means an AI-agent plugin with skills, for Claude Code, Codex or another agent. **Library** means a dependency in `dep.yaml`. There are two agentks plugins: one for using agentks, and a smaller, developer-oriented one for building and hosting libraries.
- Decided (sidhantha, 2026-09-30): the new repository starts from scratch, set up with the project-setup guide. Only what is needed moves across.
- Decided (sidhantha, 2026-09-30): this repository stops building once the new release is final, and is archived after it. Existing users get an option to update.
- Decided (sidhantha, 2026-09-30): the docs are rewritten completely. Until they are fully migrated and usable, this repository's docs are used. The skills for the new version are ready before the switch.
- Decided (sidhantha, 2026-09-30): the first Rust release is 1.0.0.
- Decided (sidhantha, 2026-09-30): the order of work is the six steps in section 01. No subtasks yet; the notes are kept consistent first.

# 05 Notes & Analysis

## 01 The order of work

| Step | Work | Needs |
|---|---|---|
| 1 | Build the Rust engine, the client and the default library, and test them end to end | — |
| 2 | Get the Neuralabs plugin marketplace running, with the two agentks plugins | step 1, so the skills describe the real tool |
| 3 | The agentks homepage | — |
| 4 | The docs migration: a complete rewrite for the new version | step 1 |
| 5 | Hosting: agentks.neuralabs.org with `/` and `/docs` | steps 3 and 4, and `agentks build` (section 04) |
| 6 | The official archival of this repository | step 5, so users have somewhere to go |

The same order is recorded as a comment on this issue. The active tracker moves into the new main repository during step 1, once the engine and the client work ([the repositories](./12_repositories-and-three-states.md)). The switch-over from this repository's docs and skills to the new ones happens at steps 4 to 5, when the new docs are complete.

## 02 The website (claude, proposed details)

| Path | Served from |
|---|---|
| `/` and everything else | The homepage's static build |
| `/docs/` | The docs, generated by `agentks build` |
| `/install.sh` (and the Windows script) | The GitHub release. A redirect rather than a copy: GitHub still serves the file and its checksums, and the server can never hand out a stale binary |

**For agents:** `/docs` also publishes each page's raw markdown and an `llms.txt` index (a plain list of pages written for AI readers). An agent can then read the docs without a browser. The skills remain the agent's main manual.

**Latest-only docs** can describe features an older binary lacks. Each feature's page says the version it arrived in ("since 1.2"). The CLI's automatic updates keep most users on the latest anyway.

## 03 The two AI plugins

| Plugin | For | Holds |
|---|---|---|
| `agentks` (usage; `agent-ks` today) | Anyone writing docs, issues or artifacts with agentks | The skills this repository ships today, rewritten for the new version |
| Library development | People who build or host their own libraries | The manifest format, the catalog entry, testing a library locally, tagging versions |

Both live in the new repository's `plugins/` folder. The marketplace repository only points at them.

## 04 Hosting needs agentks build (claude)

The website is a static site. Its `/docs` part is what Phase 3's `agentks build` produces; a Dockerfile builds it and the homepage, and serves both with nginx ([Phase 3](./07_phase-3-publishing.md)). The 1.0 release covers Phases 1 and 2 only, so Phase 3 must be finished before step 5. That gives `agentks build` its first real user: agentks's own website.

## 05 Retiring this repository (claude, proposed)

- **The final 0.x release** changes the CLI's updater to look at the new repository, or prints a notice naming the new install command. Without it, installed CLIs keep checking this repository and never see the new version.
- **Transfer before archiving.** Transferring this repository to neuralabshq and then archiving it keeps GitHub's redirects. Old install commands and links keep working, read-only.
- **A migration guide** for existing projects: install the new binary, run `agentks migrate`.
