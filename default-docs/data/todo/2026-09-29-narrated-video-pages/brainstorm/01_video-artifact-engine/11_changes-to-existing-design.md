**These are the notes, subtasks and decisions this design changes.** This thread writes only inside its own folder, so each change is listed here for whoever applies it. Every change corrects the file in place; none adds old wording beside new. The rows describe the design as it stands, including the folder form of decisions 41 to 52 in [the index](./01_index.md#the-folder-form).

## 01 The video issue

| File | Change |
|---|---|
| [issue.md](../../issue.md) | **Goal:** a video is an independent artifact in YAML: one `NN_<slug>.video.yaml` file for a short video, or a folder of small files for a longer one (`settings.json` marking it as a video, `controller.yaml` for the whole video, one file per scene, so an agent fixing one scene edits one file). The check warns when one file passes its size limit and when a video passes about four minutes of narration. It is played live in the browser from library components, with a generated voiceover; no rendered video file of any kind, cached or stored. **Done when:** the player spike and the voice spike are judged good enough. **Scope in:** the video artifact format in both forms and its schema, the standalone player page, the player, the layout system and its diagnostics, the item kinds, PowerPoint-level motion, the voice helper, the pronunciation list and the audio store, the video component categories, the authoring skill. **Scope out:** film-level motion (free keyframing, character animation, 3D); a markdown embed in the first version (it comes later); the markdown video format |
| [settings.json](../../settings.json) | `title` and `description` for the video artifact: a YAML file, or a folder of scene files, holding slides, narration and actions, played live; library-driven; voice by Kokoro through a helper |
| [01/03 The spike](../../notes/01_initial_discussion/03_the-spike.md) | The markdown format is retired; the spike's narrator carries over as the browser-voice fallback |
| [01/04 A proper video engine](../../notes/01_initial_discussion/04_video-engine.md) | Replace the proposed design (cues in HTML comments, a widget library built into the engine) with a pointer to the new design. The user's decisions in its section 04 stay |
| [01/05 Narration audio](../../notes/01_initial_discussion/05_narration-audio.md) | Model: Kokoro-82M v1.0 timestamped, 8-bit, with misaki-rs (MIT) built without its `espeak` feature, run by `agentks-voice`. Unknown words are an error, fixed by the pronunciation list in `config/video.yaml` or the video's own `pronounce:` (a single file's header, or a folder's controller). Clips: one per beat, Ogg Opus mono 24 kHz at 24 kbit/s. Delivery: one joined stream per video. Voice choice: the video's `voice`, else `config/video.yaml`, else the browser. Publishing: ship each video's stream |

Library elements are used only in video artifacts and HTML artifacts |
| [01/08 Relation to the engine migration](../../notes/01_initial_discussion/08_relation-to-the-engine-migration.md) | "Compiling the `.video.yaml` file" becomes "compiling a video, one `.video.yaml` file or a video folder, through one loader". The player is its own package, `apps/packages/agentks-video`, wrapped by an island. "What can start now" is the two spikes in the new repository |
| [01/09 Open questions](../../notes/01_initial_discussion/09_open-questions.md) | 01: two spikes, player and voice. 02: Kokoro-82M, pending sidhantha's listening test. 03: no cues; actions sit in the YAML beside their narration. 04: the player is framework-free TypeScript. Add the design's question 7, whether a scene may use its own voice, as a provisional decision: one voice per video, set in the controller |
| [01/01 Index](../../notes/01_initial_discussion/01_index.md) | Once agreed, this brainstorm graduates to a new notes group, and the index points at it |
| [T3 Format and compiler](../../subtasks/040_format-and-compiler.md) | One loader for both forms; the schema's three entries; the folder checks; errors that name the file to change; `check video` on a scene; `video info --slide` taking a number or an id and printing the scene file's path; the example compiling to the same `VideoData` in both forms |

## 02 The engine migration's notes

| File | Change |
|---|---|

| [01/02 System overview](../../../2026-09-29-rust-core-engine-migration/notes/01_overview/02_system-overview.md) | "Video pages" becomes "video artifacts". The non-goal's reason: "video artifacts play live from YAML files; no video file is ever produced" |
| [01/03 Architecture](../../../2026-09-29-rust-core-engine-migration/notes/01_overview/03_architecture.md) | Component table: the player package `apps/packages/agentks-video` and the voice helper `apps/agentks-voice`; the Rust core also compiles videos. Machine table: `~/.agentks/tools/` and `~/.agentks/audio/`. Downloads table: the voice row names the helper and the model, each checked against a SHA-256 built into the binary |
| [01/04 Flows](../../../2026-09-29-rust-core-engine-migration/notes/01_overview/04_flows.md) | Flow 5, step 7: video files name elements in typed fields, not cues. Flow 7: the build output gains `_audio/` and standalone video pages |
| [01/05 Open questions and risks](../../../2026-09-29-rust-core-engine-migration/notes/01_overview/05_open-questions-and-risks.md) | No "Video pages: the cue syntax" row. Two risks: the voice helper's native build on three platforms, mitigated by the voice spike and prebuilt ONNX Runtime libraries; and unknown words without espeak-ng, mitigated by the pronunciation list and the `video-unknown-word` error |
| [02/01 Content format](../../../2026-09-29-rust-core-engine-migration/notes/02_engine/01_content-format.md) | Section 03: the video row is `NN_name.video.yaml`, or an `NN_name/` folder whose `settings.json` says `"kind": "video"`; either is one page, compiled by Rust and played by the browser. Frontmatter: no `video` key on a docs page. Section 05: folder settings gain `kind`; with `"kind": "video"` the folder is one page, and `label`, `isCollapsible` and `collapsed` are refused. Section 07: a link to a video folder resolves to its page; a later `[[./x.video.yaml]]` or `[[./x/]]` embed becomes a player. Section 08: a video's sidebar label is its header's `title`. Section 10: no cue-syntax line |
| [02/02 Project config](../../../2026-09-29-rust-core-engine-migration/notes/02_engine/02_project-config.md) | Section 01, the files: `config/video.yaml`, holding the project's default `voice:` and its `pronounce:` list. It is optional; a project with no videos has none |
| [02/03 Rust engine](../../../2026-09-29-rust-core-engine-migration/notes/02_engine/03_rust-engine.md) | Crate layout: `crates/video` (package `agentks-video-compiler`), which reads both forms through one loader. Section 05: `kind: video` comes from a `.video.yaml` file or a video folder and carries `VideoData` and `transcript_html` instead of `body_html` |
| [02/05 Rust CLI](../../../2026-09-29-rust-core-engine-migration/notes/02_engine/05_rust-cli.md) | `check video` on a file, a folder or one scene; `video info` and `video preview` on any of them; `video schema`, `video voice`, `voice install` · `status` · `remove`; `--category` on `library find` and `library show` |
| [02/06 Machine home and build cache](../../../2026-09-29-rust-core-engine-migration/notes/02_engine/06_machine-home-and-build-cache.md) | `audio/` sits at `~/.agentks/audio/`, beside `libraries/` and `models/`, because audio is keyed by content, is right for every project and does not change with the engine. The 2026-09-29 decision that audio "may live in the build cache" allows this. `agentks cache clean` keeps the clips that videos in the scanned projects still use. Add `tools/agentks-voice/<version>/`. The model folder is `models/kokoro-82m-v1.0-timestamped-q8/` |
| [03/01 Shared UI package](../../../2026-09-29-rust-core-engine-migration/notes/03_frontend/01_shared-ui-package.md) | Page kinds: `video` carries `video: VideoData`, `transcript_html` and `audio`. Islands: the video player wraps `apps/packages/agentks-video`. Section 01: that package sits beside `agentks-ui` |
| [03/02 Client application](../../../2026-09-29-rust-core-engine-migration/notes/03_frontend/02_client-application.md) | Routes: `/_audio/<key>.opus` and `/artifacts/<path>.video` |
| [04/01 Library system](../../../2026-09-29-rust-core-engine-migration/notes/04_ecosystem/01_library-system.md) | A section on the fixed `components/<category>/` structure and its fifteen categories. The manifest gains a required `category` that matches the folder. Section 06: JSON components are read by the compiler and never served. Section 14 (security): the one sanctioned exception to "library files are sandboxed": the video compiler inlines library SVG after an allowlist that refuses `<style>`, animation elements, links and outside references and prefixes every id, because after it the SVG cannot run or load anything ([SVG safety](./08_library-components.md#svg-safety-an-allowlist)). `/_lib/` keeps serving SVG sandboxed. Per-category contracts are checked once, in Rust, by `agentks check libraries`. Section 07: a manifest-less local library follows the same structure, and so does a folder video's own `components/`, read as the library `self`. The alias rule and its validation: `self` is reserved and refused as an alias. Section 13: videos name elements in typed fields. Section 16: the default library's content follows [the day-one set](./08_library-components.md#08-the-day-one-set). This also settles [the migration's comment 003](../../../2026-09-29-rust-core-engine-migration/comments/003_2026-09-30_library-components-layout.md) |
| [04/04 Templates and init](../../../2026-09-29-rust-core-engine-migration/notes/04_ecosystem/04_templates-and-init.md) | The starter template ships `config/video.yaml` with the default voice and a `pronounce:` entry for "agentks" |
| [04/02 AI plugins and skills](../../../2026-09-29-rust-core-engine-migration/notes/04_ecosystem/02_ai-plugins-and-skills.md) | The `agentks-video` skill |
| [04/05 Video pages](../../../2026-09-29-rust-core-engine-migration/notes/04_ecosystem/05_video-pages.md) | "Video artifacts: what the engine provides", following [architecture fit](./09_architecture-fit.md): the YAML format in two forms read by one loader, no cues, the compiler crate, the standalone page first, the routes, the helper, the pronunciation list, Opus at 24 kbit/s joined into one stream per video, the machine-wide audio store, typed library fields, the player's layout diagnostics, and the site index treating a video folder as one page |
| [05/01 Repositories and layout](../../../2026-09-29-rust-core-engine-migration/notes/05_delivery/01_repositories-and-layout.md) | Main repository: `apps/packages/agentks-video/` and `apps/agentks-voice/`. Library repository: `components/<category>/` |
