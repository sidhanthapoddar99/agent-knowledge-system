# 0.3.7 — the "On this page" rail shows three heading levels, indented by level

The right-hand rail treated `#` and `##` as the same level, so a page's top
heading and its sections sat flush against each other. Nesting only began at
`###`. The rail also listed `####` and deeper, which on a long document buried
the sections a reader actually navigates by.

The rail now indents by heading level from the top — `#` flush, `##` one step,
`###` two steps — and stops there. `####` and deeper are not listed.

**No content migration. `MIN_CONTENT_VERSION` stays at `0.2.0`.** Nothing on disk
needs changing — set `engine_version: "0.3.7"` in `site.yaml` when you upgrade.

## The fix

Two rails render headings, and both had the same defect. Each one is fixed in
the same two places: the component drops the deep headings before rendering, and
the stylesheet shifts the indent scale down one step.

| Surface | Files |
|---|---|
| Docs pages (`default` + `compact` share one component) | `src/layouts/docs/default/Outline.astro`, `src/styles/docs.css` |
| Issue sub-doc pages (subtask, note, plan, agent-log) | `src/layouts/issues/default/parts/detail/SubDocMetaSidebar.astro`, `src/layouts/issues/default/styles/detail.css` |

The filter runs in the component, not in CSS. A hidden entry would still carry a
`data-outline-link` / `data-toc-link` attribute, and the scroll-spy walks that
attribute to decide which entry to highlight. Hiding with `display: none` would
have left the spy tracking rows nobody can see.

The indent classes move with it. `--depth-1` / `__level-1` is now the flush tier,
`2` is one step, `3` is two steps. The rules for levels 4 to 6 are deleted rather
than left unused, because nothing renders those classes any more.

**The symptom this fixes:** in the right-hand rail, a page's `#` title and its
`##` sections are indistinguishable, and `####` sub-points clutter the list.

## Notes

- **Z, not Y.** No content format moved. This is layout and CSS.
- **Deep headings still get IDs and still work as anchor targets.** Only the rail
  stops listing them; a `#my-h4-slug` link into the page is unaffected.
- **No theme ships an override for either rail**, so the change reaches every
  bundled theme identically.
- **Other issue rails are untouched.** The comments panel, the subtasks index and
  the Guide panel are not heading lists and were never indented by level.
