# 0.3.10 — every skill revised after audit; root agent-log status renders again

One engine fix and a full pass over the plugin. `agent-ks` goes from 0.10.1 to
0.11.1: ten Opus reviewers audited the ten skills against the skill-creator
guide, and every finding marked fix was applied.

**No content migration. `MIN_CONTENT_VERSION` stays at `0.2.0`.** Nothing on disk
needs changing — set `engine_version: "0.3.10"` in `site.yaml` when you upgrade.

**Engine `0.3.10` · floor `0.2.0` · plugin `0.11.1`** — released 2026-09-04, tag `v0.3.10`.

## Upgrade

No migration scripts. The whole chain is:

```bash
git pull
./start doctor          # full build — confirms nothing broke
# then, in site.yaml:
#   engine_version: "0.3.10"
```

Set `engine_version` last, as always. Then update the plugin:

```
/plugin marketplace update sids-plugin-marketplace
/plugin install agent-ks@sids-plugin-marketplace
/reload-plugins
```

**One CLI command is removed.** `agent-ks check links` read `dist/` and reported
links that were correct on disk as broken. It is gone. `agent-ks check link-form`
is the plugin's link check. Whether a link resolves in a browser is a renderer
question, answered by the framework's own `scripts/checks/check-links.mjs`.

## What's new

**Engine**

- A top-level agent log's `settings.json` status is read and rendered. The slot
  rule (a folder with a prefix under `100` inside a run is a slot, not a child
  run) was keyed on depth, so a `010_lp_…` log at the root of `agent-log/` was
  read as a slot and its status was never read. The rule now keys on the
  folder's name and its parent: under a run, the slot rule; elsewhere a folder
  is a run when it is `NNN_<kind>_<name>/` and a grouping folder otherwise.

**Plugin `agent-ks` 0.11.1** (from 0.10.1)

Every skill was audited by its own reviewer against the skill-creator guide and
the house rules, then fixed. The themes across all ten:

- Every command, flag, path, field and file name a skill states was checked
  against the CLI help, the engine source or the disk, and the false ones were
  corrected.
- The engine and the CLI are now the stated source of truth for what they
  implement. The bundled user guide wins only on convention the code does not
  enforce.
- Each rule carries its reason. Bare "never" rows got a why.
- SKILL.md files are leaner; facts that a reference owns moved there.
- Descriptions use the words a user types, and hand off to the right sibling.
- Framework files are written `@root/<path>` so they resolve for a consumer.
- Restart instructions say `./start --detach`.

Per skill, the largest changes:

- `agent-ks-config`: the starter template's tracker `settings.json` loads (it
  shipped a schema the engine rejects); the scaffold no longer overwrites an
  existing `.gitignore`; substitutions are portable to macOS; the template ships
  `data/README.md`; the CLAUDE.md merge is shown as three cases.
- `agent-ks-issues`: a "pick up an issue" block at the top; the precedence rule
  narrowed; per-file `draft` and `color` claims corrected; `08_agent-logs.md`
  folded away; SKILL.md under the word cap.
- `agent-ks-issue-logs`: the six kind trees moved to `references/kinds.md`; the
  round/report numbering and `--agent` are documented; the `rf` tree matches the
  template.
- `agent-ks-qna`: read the issue first; the target-issue step; `set-state` and
  `check issues --template` named; the guardrail/decision tie-break.
- `agent-ks-docs`: true failure modes (a missing `title` warns, a missing
  embed renders an error box); the `doc` read verbs; artifact theme injection
  linked, not restated.
- `agent-ks-blog`: the in-fence embed rule corrected; the content-root line;
  the tag-vocabulary command; a worked post.
- `agent-ks-artifacts`: `notes/` and `brainstorm/` only; the true cascade and
  `data-theme` behaviour per mode; `check section` as gate step 0.
- `agent-ks-cli`: `check links` removed; the exit-code and unknown-flag rows
  state what the scripts do today; the ImageMagick dependency on `img`;
  `--kind` help lists `re`; `new-round --json` carries `indexUpdated`;
  `check config` resolves a hyphenated alias and `@root` in an alias value,
  so the starter template's `@default-docs` entry is checked instead of
  skipped; the `check issues` help for `--verbose` and `--strict` says what
  they do.
- Every skill's description parses as strict YAML. Three carried a bare `: `
  inside the value; a strict loader rejected them.
- Every sentence in every skill was rewritten in plain technical English
  (ASD-STE100): one instruction per sentence, active voice, each term defined
  where it first appears, no idioms. Facts, commands and paths are unchanged.
  Sentences over 20 words fell from 132 to 67 across the ten skills.
- `agent-ks-quick-idea-note`: the routing search finds shipped features
  (`--status all`); adding a vocabulary value needs its description.
- `agent-ks-index-check`: a log's index leaf is found by pattern; `check
  link-form` runs first; the agent gets Bash and runs on sonnet.

The audit log, one report per skill and the verdict on every finding, lives in
the framework tracker under `2026-04-19-docs-phase-2/agent-log/040_au_skill-creator-audit/`.
