title: "Page data interface — the one set of shapes the client and the static build read"

The frontend asks for data by name and receives final, ready-to-display JSON; it recomputes nothing. The same shapes feed two consumers: the local client over the `/api` WebSocket, and the static renderer during `agentks build`. This leaf defines those shapes in `agentks-api` and implements the functions in `agentks-site` that produce them, so the server and the build cannot drift.

# 01 To Do
- [ ] **The request names and their results** ([02/03](../../notes/02_engine/03_rust-engine.md) section 05):

| Request | Returns |
|---|---|
| `manifest` | Site identity, logo, theme CSS URL and hash, navbar, footer, sections (name, type, layout style, base URL, hash), the route table, the engine and API versions |
| `page` (by URL) | One page's data |
| `sidebar` (by section) | The section's tree: label, URL, kind, order, collapsed default, children, and the tree's hash |
| `issues-index` (by tracker) | Every issue with derived fields; the filter option lists |
| `issue` (by id) | One issue with anatomy sections, subtasks, plans, logs, comments, each with status and category |
| `blog-index` (by section) | Posts newest first, with dates, authors and tags |
| `custom` (by page) | The YAML data of a built-in custom page |
| `render` (Phase 2) | Body HTML and outline of unsaved markdown, for the live preview |

- [ ] **The page shape** as in [02/03](../../notes/02_engine/03_rust-engine.md) section 05: `url`, `hash`, `section`, `kind`, `layout`, `source`, `title`, `description`, `frontmatter`, `body_html`, `outline`, `breadcrumbs`, `prev`, `next`, `diagrams`, `errors`; diagram pages carry source and options instead of `body_html`; artifact pages carry their URL and options. Field names are snake_case on the wire.
- [ ] **Every value is final**: no prefix to strip, list to sort, status to map or link to resolve in the browser.
- [ ] **Every response carries its hash**, so the browser caches by it and asks again only when it changes ([090/20](../090_frontend-performance/20_data-cache-indexeddb.md)).
- [ ] **`api_version`** in the manifest: bumped on any breaking change to a shape; the client refuses a mismatch and reloads ([140/50 protocol version handshake](../140_versioning-and-migrations/50_protocol-version-handshake.md)).
- [ ] **One schema file**: derive a JSON Schema from the Rust types (`schemars`) into `apps/agentks-engine/schema/api.schema.json`, regenerated by `ctl build` and checked in CI (a stale file fails the gate). The UI package type-checks its data against it ([080/20](../080_ui-and-client/20_shared-ui-package.md)).
- [ ] **Producers in `agentks-site`**: `site.manifest()`, `site.page(url)`, `site.sidebar(section)`, … each returning `agentks-api` types, used by `agentks-server` and by `agentks build`.
- [ ] **Fixtures for the frontend**: a test that writes the JSON for a handful of corpus pages (one per kind and layout) into `apps/packages/agentks-ui/fixtures/`, so components are developed and tested against real data.

## Guardrails
- The shapes are a data contract, not rules: no function, formula or ordering logic crosses into TypeScript.
- Adding an optional field is not breaking; removing or renaming one is, and bumps `api_version`.

## Done when
- Every request above answers for the corpus through `agentks-site`, and the server and `agentks build` call the same functions (checked by a test that renders one page both ways and compares the JSON).
- `api.schema.json` is generated, committed and validated in CI; every fixture JSON validates against it.

# 04 Decisions
- Decided (sidhantha, 2026-09-29): the frontend holds display and UI logic only; every rule stays in Rust; no WASM.

# 05 Notes & Analysis
## 01 Open: generated or hand-written TypeScript types
sidhantha decided on 2026-09-29 that "no TypeScript is generated from Rust". The frontend note ([03/01](../../notes/03_frontend/01_shared-ui-package.md)) proposes generating data-shape types (for example with `ts-rs`) and reads that decision as about rules, not shapes; this needs sidhantha's confirmation ([open questions](../../notes/01_overview/05_open-questions-and-risks.md)). This leaf works either way: it publishes the JSON Schema, and [080/20](../080_ui-and-client/20_shared-ui-package.md) either generates types from it or checks hand-written types against it.

## Watch out
- Keep `body_html` out of the manifest and indexes; they must stay small enough to send on every connect.
