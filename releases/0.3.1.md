# 0.3.1 — `./start` stops building on every dev start, and checks your version before it does anything

The bare `./start` used to run a full production build before handing you a dev
server. It no longer does: dev starts in **2.4 s and writes 0.4 MB** where it used
to take **~9.5 s and write ~100 MB** of `dist/` that dev never reads. The build
moved to `./start doctor`, which is what you run before you publish. Every
launching command now also checks `site.yaml → engine_version` **before** starting,
so a version problem stops the command instead of surfacing as a 500 on your first
page load — or, in `preview`, not surfacing at all.

**No content migration. `MIN_CONTENT_VERSION` stays at `0.2.0`.** Nothing on disk
needs changing — set `engine_version: "0.3.1"` in `site.yaml` when you upgrade.

Plugin: **`agent-ks` 0.8.5** — unchanged this release.

**Engine `0.3.1` · floor `0.2.0` · plugin `0.8.5`** — released 2026-08-08, tag `v0.3.1`.

## Breaking — one behaviour change, no content change

### `./start` no longer builds

**The symptom if you relied on it:** a build-only error now reaches you later than
it used to. Dev resolves one URL per request through `matchServerRoute()`; the
build enumerates every address through `getStaticPaths()`. A duplicate URL fails
the build and is **invisible in dev** — so it used to stop you at start #1, and now
it waits until you publish.

**What to do:** run `./start doctor` before you publish. It is the old preflight
build, at the cadence where the answer matters. Nothing else changes; `./start`
still gives you the same dev server on the same port.

This was measured before it was decided: ~6 s and ~100 MB per invocation, on a
command typed about twenty times a day, to answer a question that only matters at
publish time. Dev was verified never to read `dist/` by deleting it and serving
every route.

### `start.ps1` is deleted

**The symptom:** `.\start.ps1` is not found on Windows.

**What to do:** use **`.\start.cmd`** — same arguments, same behaviour. It execs
the same `scripts/start.mjs` every other platform runs, so there is no longer a
Windows port that can drift out of step. (The PowerShell twin was 397 lines, and
only ever parse-verified.)

## Upgrade

No migration scripts. The whole chain is:

```bash
git pull
./start doctor          # full build — confirms nothing broke
# then, in site.yaml:
#   engine_version: "0.3.1"
```

Set `engine_version` last, as always.

## What's new

### The version precheck runs before anything starts

Every command that launches or builds — `dev`, `preview`, `build`, `doctor`, and
any forwarded script — compares your content's declared version against the
engine's supported range first:

```
[start] content 0.3.1 · engine 0.3.1 (floor 0.2.0)
```

Out of range, it stops and names the exact scripts to run, in order, instead of
leaving you with a stack trace.

The engine already had this rule. What it could not control is *when* it fires:
in `dev` it fires at the **first request**, after the server has already reported
"ready", so the server looks healthy and every page 500s. In **`preview` it never
fired at all** — preview serves prebuilt files and never loads config, so a
`dist/` built from unmigrated content was served in silence. That second one is
the gap worth knowing about.

Set `START_SKIP_VERSION_CHECK=1` to bypass it; the engine still refuses the
content itself.

### `./start` grew a real CLI

`--help`, and server-control verbs that never prompt: `./start status`, `stop`,
`logs [--follow]`, `clean`. `--detach` backgrounds a server; without it, `Ctrl-C`
stops what you started. Full reference, with the measured cost of every command:
[Repo scripts and the `./start` command](../default-docs/data/dev-docs/01_overview/02_scripts.md).

### Group the issue tracker by date

The tracker's **Group** menu adds **Date created** and **Date updated**. They
bucket into **Today**, **Past week** (1–7 days back), then by calendar month,
newest first. The bucketing runs in the browser against your clock, so a static
build cannot freeze "Today" at the moment it was built.

## Fixed

### The footer shipped four dead links on every page

`footer.yaml` still carried the starter template's placeholder hrefs —
`/docs/getting-started`, `/docs/guides`, `/docs/api`, `/contact` — none of which
are sections of this site. On a 1039-page build that is **4157 broken links**, in
the one component that appears on every page.

Fixed, and fixed in a way that cannot recur: internal footer links now use
`page:` (a name from `site.yaml → pages`) instead of a hardcoded `href`, so they
follow a section's `base_url` rather than restating it. **If you started from the
template, check your own `footer.yaml` — you have inherited the same four links.**

### One implementation of the launcher, not three

`start`, `start.cmd` and the deleted `start.ps1` are now three-line shims over
`scripts/start.mjs`. The bash script was 447 lines and the PowerShell twin 397,
and every feature had to be written twice.

## Notes

- **The floor does not move.** Nothing in this release changes a content format,
  so no migration ships and 0.2.0 content still loads unmigrated. `MIN_CONTENT_VERSION`
  means "oldest content that still works", not "newest release available".
- **Z, not Y.** The launcher rework is the largest change here and it is still a
  Z-place bump, because the version series gates *content format* and no format
  moved. The `./start` behaviour change is user-visible, which is why it leads the
  note rather than the number.
- **`experimental.incrementalBuild` was evaluated and left off.** It works — 6.25 s
  → 4.20 s, per-page granularity, 5/5 correctness tests — but a wrong cache key
  produces a stale page with exit code 0 and no warning, and about 98% of runs are
  dev, which does not build. Enable with `INCREMENTAL_BUILD=1` in `.env`, and run
  `scripts/checks/check-incremental-staleness.mjs` before trusting the output.
- **The repo's check scripts moved** to `scripts/checks/`. Development-stage only;
  nothing here ships to a consumer.
- **Windows is untested on a Windows host.** `start.cmd` is exercised by the same
  `scripts/start.mjs` every platform runs, but nobody has run it natively. Report
  anything odd.
