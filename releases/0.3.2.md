# 0.3.2 — embedded diagrams and standalone images sit in the middle of the page

An excalidraw scene narrower than the text column used to sit against the left
edge, even though its container was already told to centre. A standalone image did
the same. Both now centre. This is a stylesheet change only.

**No content migration. `MIN_CONTENT_VERSION` stays at `0.2.0`.** Nothing on disk
needs changing — set `engine_version: "0.3.2"` in `site.yaml` when you upgrade.

Plugin: **`agent-ks` 0.8.5** — unchanged this release.

**Engine `0.3.2` · floor `0.2.0` · plugin `0.8.5`** — released 2026-08-10, tag `v0.3.2`.

## Fixed

### An embedded diagram narrower than the page was left-aligned

**The symptom:** you embed `![Scene](./assets/scene.excalidraw)`, the drawing is
480 px wide, the content column is 800 px, and the drawing hugs the left edge with
a wide empty gap on the right. Mermaid and Graphviz blocks did the same thing.

**The cause:** the reset stylesheet declares `svg { display: block }`. A block
element does not respond to the container's `text-align: center`, so
`.markdown-content .diagram`'s centring never reached the drawing inside it.
draw.io was unaffected — its host element centres with flexbox instead.

**The fix:** `.markdown-content .diagram svg` now carries auto left and right
margins, which centre the block itself. Nothing to do on your side.

### A standalone image was left-aligned

**The symptom:** an image on its own line rendered flush left, which reads as a
misplaced figure next to the diagrams above and below it.

**The fix:** an image that is the only thing in its paragraph is now centred, in
both the plain form `![alt](pic.png)` and the linked form
`[![alt](pic.png)](target)`. An image used **inside a sentence** — a badge, a small
inline icon — is untouched and stays where it is.

**If you had centred an image yourself** with a raw `<div align="center">` or
inline HTML wrapper, you can delete the wrapper. Leaving it in place is harmless.
