# 0.3.0 — Astro 7, and the dev tooling stops shipping to your readers

The engine moves from Astro 5.17.1 to **7.2.0** (Vite 8, Rolldown), a tracker
index stops rendering 861 pages to draw a table of titles, and a production build
stops emitting the live editor and 426 client chunks no reader could ever reach.

**No content migration. `MIN_CONTENT_VERSION` stays at `0.2.0`.** Nothing on disk
needs changing — set `engine_version: "0.3.0"` in `site.yaml` when you upgrade.
The middle place moves because the *engine* moved two majors, not because your
content did.

Plugin: **`agent-ks` 0.8.5** — unchanged this release. Nothing here is a plugin
change.

**Engine `0.3.0` · floor `0.2.0` · plugin `0.8.5`** — released 2026-08-08, tag `v0.3.0`.

## Breaking — read this before you upgrade

### Node 22.12 is now the floor

Astro 7 requires it. **On Node 20 or 21 the build does not start.** Check with
`node --version` before you upgrade; there is nothing to do in your content.

### A user theme directory can no longer be called `default`

`@theme/default` always meant the framework's built-in theme, which every user
theme extends. A user directory claiming that name silently shadowed it.

**Symptom if this is you:** startup now throws, naming the directory. Rename it
and update the `theme` value in `site.yaml` plus any `extends:` pointing at it.
This was already broken; it now says so instead of misresolving.

### A theme that inherits in a circle now fails at startup

`a extends b extends a` used to hang or half-resolve depending on which entry
point loaded first. It now throws with the full chain printed. Again: previously
broken, now loud.

### `replace`-mode themes must satisfy 12 more variables

`required_variables` grew from **53 to 65**. The additions are all variables a
shipped layout already reads — `--font-weight-normal`, `--display-sm`,
`--display-md`, `--spacing-2xl`, `--spacing-3xl`, `--border-radius-full`,
`--shadow-xl`, `--sidebar-width`, `--navbar-height`, `--outline-width`,
`--max-width-primary`, `--max-width-secondary`.

**This only affects `override_mode: replace`**, which drops the parent theme and
keeps only what the contract names. If yours is `merge` or `override` (the
common case) you inherit them and there is nothing to do. If it is `replace` and
you skip this, the affected layouts lose their sizing — **no error, just wrong
layout**, which is why it is listed here rather than left to be discovered.

No migration script ships for this one, and that is deliberate: a script can add
a variable name but cannot choose your value.

## Fixed

### The tracker index was rendering every issue body to draw a table

The index loader parsed and rendered **861 issue bodies** to build a list of
titles. First request took 3.2 s and grew linearly with the tracker.

It now reads frontmatter only. **A docs page ships static HTML plus one
stylesheet and loads zero JavaScript chunks.**

### The build shipped the live editor to every consumer

`dist/` contained `/editor` — a working editor UI wired to save endpoints that
exist only in dev, so **broken on arrival** — plus the three `/api/dev/*`
endpoints and 426 client chunks behind them.

They were routes because they sat in `src/pages/`, which Astro builds
unconditionally with no integration consulted. They now live in
`src/dev-tools/routes/` and are injected only under `command === 'dev'`.

```
  dist bytes    108,959,585 →   97,676,286    -10.4%
  _astro bytes   23,077,518 →   11,795,276    -48.9%
  _astro files          582 →          156      -426
  files in dist       1,941 →        1,511      -430
```

**Half of `_astro` was the editor.** Nothing you author changes; your deploys get
430 fewer files, permanently.

### Derived `updated` dates went stale in dev until you restarted

The dev server watched `.git/HEAD` and the active branch ref, and never fired —
because Vite hardcodes `**/.git/**` as the first entry of its watcher ignore
list, so the paths registered and every event for them was discarded.

This was never an Astro 7 regression; that ignore list has shipped in Vite for
years. A commit now refreshes the date with no restart.

### Every page carried a 65 KB inline stylesheet

The theme CSS is a `<link>` now, so it is fetched once and cached instead of
re-sent with every page.

### A missing docs page answered `200` with a fully styled body

It answers `404`. The sidebar shell is still rendered on purpose, so the tree
stays navigable while a file is mid-edit — but the **status code** is now honest,
which matters to every link checker that trusts it.

`dist/404.html` also exists for the first time.

## Changed

- **Five code-fence languages added** — `astro`, `jsonc`, `nginx`, `diff`, and
  `dotenv` (with `env` as an alias). They highlight server-side, so they cost a
  reader nothing.
- **Dark-mode task checkboxes** read correctly. They were drawn with a hardcoded
  colour that vanished on a dark canvas.
- **Subtask state buttons are disabled in a built site.** They wrote through a
  dev-only endpoint, so on a published site they looked live and did nothing.
- **`./start` drives Astro's server lifecycle through its lock file.** Astro 7
  backgrounds itself, so killing the process you launched leaves the daemon
  running — this leaked eleven dev servers during the upgrade and one that held
  1.19 GB for 18 hours. New verbs: `./start stop | status | logs [dev|preview]`.
  **`Ctrl-C` behaves exactly as before.** `./start clean` now stops servers before
  wiping `.astro/`, which holds the lock.
- **21 dependency minors**, including mermaid 11.12.2 → 11.16.1, which adds about
  a dozen diagram types (swimlanes, treemap, radar, venn, wardley, ishikawa,
  abnf, ebnf, peg, railroad, cynefin, packet). Each is a lazily-loaded chunk; you
  download only the one your page uses.

## Notes

### If diagrams stop rendering in dev

Mermaid, Graphviz, Excalidraw and draw.io render from Vite's pre-bundled
dependency cache in dev. If that cache goes stale the imports answer `504`, the
diagram silently shows its raw source, and **no error appears on the page**.

```bash
./start clean dev     # wipes .astro/, dist/, node_modules/.vite/
```

A production build cannot have this — Rollup follows the imports at build time
and emits real chunks.

### What did not change

Every markdown file, `settings.json`, frontmatter field and link form is
untouched. This release is engine-side. If your content loaded on 0.2.x it loads
here, and the only edit you make is the `engine_version` line.
