# The presence server survived a dead-code sweep — deliberately, and it is yours

[The Astro 7 issue's dead-code sweep](../../2026-08-07-astro-7-and-load-time-refactor/subtasks/050_cleanup/010_dead-code-sweep.md)
was told to delete `presence.ts` as dead code. **It was not deleted. Sid ruled to
keep it, on the grounds that multi-user editing is wanted — later, but wanted.**

Recording it here because this issue owns the feature, and the next person who
runs a cleanup will find the same "dead" verdict and needs to know it was already
argued.

## What is actually on disk, verified rather than assumed

The audit's evidence is correct, and I reproduced all of it:

| Claim | Verified |
|---|---|
| No `EventSource` anywhere in `src/` | ✅ zero |
| Nothing POSTs `/__editor/presence` | ✅ zero |
| Nothing GETs `/__editor/events` | ✅ zero |
| `handleAction('join')` is never called | ✅ so `users` is always empty |

**So every broadcast is a permanent no-op**, and the cache-inspector's presence row
always reads zero users.

But it is **not** an orphan file, which is what the sweep's one-line summary
implied. It is wired into three places:

- `integration.ts` constructs `PresenceManager` and starts its cleanup timer
- `yjs-sync.ts` calls `updateLatency()` and `handleAction({type:'cursor-clear'})`
- `cache-inspector` renders `presence.users` and `presence.userCount`

## What this means for this issue

**The server half of presence already exists.** Roughly 267 lines in `presence.ts`,
about 40 more in `middleware.ts`, and 6 config keys nothing reads yet. Join/leave,
per-user state, cursor actions, latency, stale-user cleanup and SSE broadcast are
all written.

**What is missing is the client.** Nothing opens an `EventSource`, nothing posts a
join, so nothing ever populates the user list.

So the work this issue describes — *"live users visible, presence cursors in CM6"* —
is closer than the tracker suggests. It is a client-side job against a server that
is already there, not a feature from zero.

⚠️ **One caution before building against it:** the server half has never had a
client, so it has never actually run with users in it. Treat it as untested rather
than working. `handleAction('join')` having zero call sites means that code path
has executed exactly never.

## The six unread config keys

They sit under `editor.presence` in the config and nothing reads them. Worth
confirming they still describe what you want before wiring a client to them — a
config surface designed before its client is usually wrong in a detail or two.
