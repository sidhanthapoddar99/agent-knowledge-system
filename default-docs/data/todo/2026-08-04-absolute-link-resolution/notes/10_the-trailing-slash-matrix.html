The trailing-slash matrix

One link, four combinations. The markdown never changes and it is correct on disk in all four. Only two things vary — what the renderer writes into the href, and whether the server puts a slash on the end of the URL. Docs only; blog and issues take a different code path.

One rule decides all four cells. A browser resolves a relative href against the directory portion of the address it is currently on. The trailing slash is the only thing that says where the directory ends.

address /a/b/c → c is a file inside /a/b/  →  base is /a/b/ address /a/b/c/ → c is a folder I am in  →  base is /a/b/c/

The two addresses differ by exactly one segment. So does the shift. That is why the four cells form two matching pairs and two broken ones — and why no fixed value of the shift can be right in both rows.

Measured 2026-08-04 with trailingSlash: 'always' also set: 1,245 in-body links, 4 broken — the same four missing anchors as the top-left cell.

A perfect diagonal — and that is the proof there is no right answer

The renderer writes the href at build time. Which row the reader lands in is decided at request time, by a server the renderer has never met. The rows differ by exactly one URL segment, which is exactly the amount the shift changes — so no constant offset satisfies both, including zero.

Both previous rounds measured one row and concluded the other did not exist. On 2026-08-03 the shift was added having seen only the bottom row, through a tool that reads dist/ and constructs each page URL with a slash: it read as 418 → 55. On 2026-08-04 it was removed having seen only the top row — dev, preview, and a browser — and that read as a clean fix. astro dev and astro preview are route tables and never add the slash; a static host is a file server and always does. So testing dev against preview is testing one row twice.

Where the tree stands now — the top-left cell

Both attempts are reverted. No shift, no trailingSlash setting. The renderer emits the author's own relative shape, which is correct for every URL the site's own navigation produces.

That is a deliberate choice of column, not a solution. Dev is where this project is actually used, so dev is the column that has to work. The bottom row stays wrong until absolute resolution lands.

trailingSlash: 'always' also carried a second, unrecoverable cost: it 404s the whole /artifacts/<file>.html route, whose URLs end in a file extension and can never take a trailing slash. This page is served by that route.

The way out — delete the question

Resolve internal links to root-absolute at render time, so the emitted href is /user-guide/getting-started/installation and there is no directory portion to resolve against. The slash stops mattering rather than being made uniform — which also survives a CDN that rewrites URLs, and the Comprehensive panel, which renders a subtask's HTML at a URL that is not the subtask's own.

Decided 2026-06-09. The one missing ingredient: the section's base_url never reaches the parser layer, so the postprocessor cannot know which section it is in. Threading that one field through deletes this entire matrix.

Companion to this issue's note “What happened, and why it took two rounds”. Every number here was measured on 2026-08-04 against a running server — dev, preview, and a real file server over dist/ — never read off the filesystem.
