The description is accurate and appropriately pushy ("even a one-line change"). What it lacks is the user's vocabulary. It names the file (`theme.yaml`) rather than the symptom (colours, dark mode, logo, font, port, the site will not start), and those symptoms are the majority of real config prompts.

## Proposed description

> Set up and configure an agent-knowledge-system project. Use it for a new project from the starter template, a new top-level section, and every file under config/ (site.yaml, navbar.yaml, footer.yaml), the framework .env and its port, path aliases and routes, themes and theme.yaml — colours, fonts, dark mode, the logo and favicon — layout styles and custom layouts, custom pages (home, about, countdown) and their YAML, and format migrations when the site refuses to start with an engine-version error. Trigger it for any setup or configuration question, even a one-line change, and whenever the site will not start. Content inside a section belongs to agent-ks-docs, agent-ks-blog or agent-ks-issues.

Adds the symptom words (colours, dark mode, logo, favicon, port, refuses to start) and names the three custom-page kinds. Keeps the closing hand-off sentence unchanged, because it is what stops finding 4's near-miss.

## The dry run

Prompt: "Set up docs for this repo. We don't have any yet — it's a Python package."

1. SKILL.md, triage row 1, straight to `01_new-project.md`. No wasted reading; the triage table did its job in one hop.
2. Step 1 pre-flight: three `test -f` lines, clear. It never checks `.gitignore`, which is the file step 6 goes on to overwrite (finding 2).
3. Step 2: `CLAUDE_PLUGIN_ROOT` is unset in my shell, so the `readlink -f` fallback ran. It resolves correctly against the source layout — the only reason it failed here is that the installed plugin is frozen at 0.9.0. Not a defect.
4. Steps 3-5: scope, four identity questions, a literal confirm block. Nothing to guess. The best part of the skill.
5. Step 6: I would have run GNU-only `sed` (finding 3) and silently replaced this repo's 37-line `.gitignore` (finding 2). The confirm block I had just shown the user listed `.gitignore` as one of nine lines and did not say "replaces yours".
6. Step 7 is where I was actually lost: "merge into an existing `## Documentation` section" has no defined output and no example (finding 10).
7. Step 8: `agent-ks check config <root>/config` exits 0 — I ran it against the template. It cannot see the broken tracker settings (finding 1), so the flow ends with a green check and a project whose `/issues` route throws.
8. Missing when I needed it: what `data/README.md` should contain, and whether `.env.example` (which rsync copies to the project root) is meant to be there — the result tree and the confirm plan both omit it.
9. Did not need: nothing. Every line of 01 is load-bearing.
